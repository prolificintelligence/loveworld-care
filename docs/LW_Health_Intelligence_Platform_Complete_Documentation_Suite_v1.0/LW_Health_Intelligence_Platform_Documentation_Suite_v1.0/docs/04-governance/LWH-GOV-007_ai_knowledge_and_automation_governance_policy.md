# AI, knowledge and automation governance

## Policy scope

Register every assistant, algorithm, rule engine and automation by intended use, owner, user, population/setting, data class, tools, review authority, model/source version, limitations, fallback and retirement. Distinguish low-consequence clerical work, human-reviewed drafts, approved deterministic clinical pathways and consequential institutional/clinical/financial acts. Institutional seniority or a model confidence score cannot expand permissions.

## Knowledge/content adoption

Sources are primary/authoritative where applicable, versioned, applicable and licensed for intended use. Clinical content has qualified author/reviewer and explicit exclusions/unknown-input handling. Ministry policy has the authorised institutional wording. Expired, withdrawn or unsupported material is not presented as current advice. A retrieved document can contain malicious or incorrect instructions; it remains evidence, not runtime authority.

## Data and learning

Use minimum authorised context. Protect patient/family/custodian boundaries and separate anonymous institutional analytics from protected clinical memory. Patient facts grow through source-attributed, correctable context. Model training or evaluation reuse requires its own approved purpose/data arrangement; no uncontrolled production fine-tuning or silent self-modifying clinical policy. Keep feedback, model version, evaluation and release decision separately auditable.

## Review and evaluation

Clinical users review consequential summaries, assessments, orders, treatment changes and documentation before intentional signing. Directorate staff decide affiliation/sanctions; authorised finance approves funding/refunds; custodians control protected sharing. Evaluate source fidelity, negation, contradictions, omissions, wrong subject, missing critical facts, maternal/paediatric scope, injection/tool abuse, accessibility, language context, cost and workload versus manual baseline. A critical safety/permission failure blocks that use case.

## Provider/model change and incidents

Review provider processing location, retention, subprocessors, security, permitted data and contractual use. Version changes rerun applicable evaluations and approvals; a provider upgrade does not inherit all previous clinical validation. Monitor corrections, harms, drift, costs and dependency failure. Provide kill/restrict controls per use case/service while retaining core care/reporting workflows. Resume after evidence and authorised review.

## Accountability

Clinical governance owns clinical intended use; standards/information owners own institutional automation; security enforces tool/data bounds; privacy reviews processing; AI engineering maintains evaluations and deployment; finance approves cost envelopes. Named persons are assigned at activation. This policy adopts a governance structure, not a claim that NIST/WHO endorses the platform or that any model is clinically certified.
