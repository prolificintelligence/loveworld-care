## Fixes and engineering evidence

The old initial-affiliation flow accepted duplicated or incomplete inspection findings, allowed one criterion's file to support another, and did not recheck evidence expiry before positive recommendations/decisions. Corrected-clock isolated reproductions obtained **200** for expired inspection evidence, expired decision evidence and unrestricted recommendation with an unmet required finding. The initial regression run recorded eight failures and one baseline pass; failed evidence is retained. None of these were production incidents or proof of a qualified scanner.

The initial flow now records every configured mandatory criterion exactly once, validates references against their application and actual criterion, requires current CLEAN evidence for MET, and rechecks current required evidence before positive recommendation/decision. A required unmet or not-observed finding prevents unrestricted recognition. Conditional recognition remains a separate independent central decision with explicit conditions. Truthful NOT_MET/NOT_OBSERVED findings can omit evidence; the UI no longer requires invented attachments for those observations. Adverse decisions remain possible with expired evidence, without granting recognition. These guards use the configured requirement flags and add no institutional threshold or approval authority.

Original evidence is not edited to simulate expiry. Tests advance the isolated authoritative metadata clock by 20 minutes, leaving sessions/grants valid, then restore it. Synthetic CLEAN rows are explicitly **metadata-only, not a successful scan or real uploaded file**. Actual upload scanning remains mandatory; unconfigured scanner/storage prerequisites still exclude uploads.
