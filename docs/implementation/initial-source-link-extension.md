# Explicit initial inspection lineage

`LWH-EXT-INITIAL-FINDING-LINK-001` records a current independent reviewer's explicit association between an actual historical initial inspection criterion and an existing institutional finding. It never manufactures a finding, copies a resolution, supplies current scanned proof or grants recognition.

Confirmation requires current access to both dossiers, the exact current application/case/finding versions, the actual inspection ID and its immutable attestation version. Resource identity, facility and retained criterion version must match. The source must be exactly one actual NOT_MET/NOT_OBSERVED observation, with its original signed inspector and consecutive assignment → screening → evidence review → attestation chain. MET, unbound/legacy-shaped, future or mismatched source records are refused. New links from withdrawn sources are refused. Historical source evidence may have expired: this is provenance context, not current evidence qualification.

Only the personally assigned current standards reviewer can confirm, with actual reason and intent, independently of source/target inspectors and applicants/respondents. Initial-application locking precedes facility locking, matching the existing initial workflow. Institutional commands retain their existing transaction serialization. Exact duplicates are refused even with a different operation key; same-key replay returns the historical receipt subject to current authority. No default source, due date, officer, approval or scanned result is invented.

The immutable encrypted association retains original observation, inspector, initial reviewer, applicant, source times, inspection/attestation identity and application version/state at confirmation. The target finding, case, evidence and original source history are unchanged. A current authorised reviewer may record a retained retraction annotation, including after case completion. That retracts context only; it does not reverse recognition or erase source facts. Retracted sources cannot be silently resurrected. Actual adverse decisions or new work require their own lifecycle actions.

Private history displays all associations/retractions (bounded at 20 distinct initial inspections per finding). Initial attestation candidates are paged ten versions at a time and preserve rejected/unavailable source reasons. Both dossier scopes are checked. UI selection and confirmation are explicit; current initial application state/version remain visible, and local annotation drafts clear on actor/case/finding-version changes.

Storage reuses the existing protected schema-9 journal; no migration, dependency or host is added. Journal versions denote observed target-finding versions, not a new workflow transition. Form capture and team/plan/response/resolution controls remain separate. Full generic capture, roster/policy, notice/service/appeal/offline and actual-role/device/adoption semantics remain open. Synthetic metadata qualifies no malware scan, file, capacity or operating approval. Rollback requires a qualified preserving schema-9-compatible artifact; never restore old business data or delete newer history.
