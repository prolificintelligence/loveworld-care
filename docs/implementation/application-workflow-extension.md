# Initial application correction and withdrawal extension

`LWH-EXT-APPLICATION-001` records initial-affiliation correction requests, responses, withdrawal and exact inspection links in existing immutable Application revision snapshots. It does not change canonical IDs, adopt criteria or supply real operating approval. Canonical FRM-010's full finding/plan/ownership/deadline meaning remains broader than this criterion-scoped implementation.

Only the personally assigned current reviewer can return an inspected/recommended case. The request retains its criteria and reason, clears the current recommendation/assignments and enters CORRECTION_REQUIRED. An authorised scoped applicant responds once to every requested criterion. Referenced evidence must be current, CLEAN and from the same application/criterion; all mandatory submission evidence and the retained criterion set must remain current. Resubmission enters SUBMITTED and requires fresh assignment, inspection and recommendation. It never resolves a finding or grants recognition.

Each new inspection is explicitly linked to its immutable application revision. Positive disposition uses that exact revision link, not timestamp ordering. Legacy unbound attestations fail closed and can enter correction for fresh attestation; no old evidence is rewritten. Production had no dossiers requiring conversion. Applicant/respondent identities and every historical inspector/reviewer remain in segregation checks, preventing reassignment from creating an eligible final decider or swapping an inspector into the reviewer role.

Withdrawal requires current scoped applicant authority, expected version, reason and explicit intent. It is available only before DECIDED/WITHDRAWN, changes only the application and retains all evidence, inspections, prior decisions and facility affiliation. Immutable receipts remain historical facts; current permissions still govern replay. Dossier history is paged by version, with the active correction request resolved separately from any displayed historical page.

No new table or migration is used. Request/response/withdrawal metadata is an additive snapshot extension. Resubmission emits the existing application-submitted event meaning; correction and withdrawal use the explicit extension contract. Scanner acceptance is unchanged and remains fail closed. There is no automatic email, invented due date, appeal decision or service activation. Full notice/appeal/offline/capture equivalence and actual-role/device acceptance remain open.
