# Canonical conformance register

This register covers every baseline form, field, screen, state family and interface. It is an engineering crosswalk with explicit exceptions. It does not accept the suite, adopt an extension or approve operation.

Run `python scripts/build_conformance_register.py` in the existing workspace environment to regenerate the JSON and five CSV views. Run with `--check` to reject stale output. CI verifies the complete register against the immutable 78-document baseline, typed request models and the effective institutional API routes. Legacy/demo applications never supply mappings.

`canonical-register.json` retains original field identity, requiredness, type, rule and source. Candidate bindings include actual typed properties, requiredness differences and source hashes. Implementation/source references use explicitly labelled `sha256_lf` text fingerprints so Windows checkout line endings do not change traceability. Controlled-document integrity still checks exact original bytes against the baseline manifest; deployment source verification retains raw-byte hashes. The form rows link handlers, permission/validation/persistence source candidates and existing engineering test candidates. These references are starting points for review, not assertions that every field has passed those tests. Schema definitions are retained so references and enum/range constraints can be inspected. Generic canonical capture envelopes and split native commands remain distinct.

Screen links associate the current platform page with its domain. They do not establish 75 individual screen implementations. State rows retain the entire canonical state/guard/effect text and source candidates. Each transition still needs its own wrong-role, wrong-subject, expired-authority, wrong-version, replay, missing-evidence, reversed-order and outage proof. Interfaces retain all 52 capture routes, 15 commands and 15 query families; path matching alone never establishes semantics.

The original automated inventory found 47 forms with candidate typed-route mappings, four form mapping gaps, 48 name/alias field candidates and 307 field-mapping gaps. The initial-affiliation and correction increments now record [19 partial field proofs](director-proofs.json), 300 explicit field-mapping gaps, 36 automatic candidates and partial transition evidence for STM-002/003. The [application workflow extension](../application-workflow-extension.md) describes the narrower initial correction contract. Generated status counts distinguish reviewed records from automatic candidates. Exact executions belong to release evidence; a test reference alone is not a pass claim. Native command guards and persistence have bounded regression evidence, while canonical tagged missingness, broader capture meaning, adoption and actual-role acceptance remain open. All 75 screen qualifications remain open; source/page links do not prove human use. Rights requests, programme funding, downtime/sync and optional ERP retain form mapping gaps; unmapped does not prove every related capability absent.

The initial affiliation guards now check every required criterion once, reject duplicated or cross-criterion proof references, require current CLEAN evidence for MET, and recheck evidence before positive recommendations/decisions. A required unmet/not-observed finding blocks unrestricted recognition; conditional recognition still requires a separate central decision and explicit conditions. Honest non-MET observations can omit evidence without fabricating a successful scan. Adverse decision history remains possible when evidence expires. These are engineering guards against the configured requirements, not adopted criteria or scanner qualification. Original evidence, inspections and decisions remain retained.

Director-first review starts with forms 001–018 and screens 001–030: registry → affiliation → returns → independent verification → permitted intelligence → accepted intervention/outcome. Resolve the field-specific exceptions before advancing claims. Record explicit typed extensions for owner review; preserve baseline meanings and actual adoption dependencies. The existing clinical extension register remains applicable.

Formal acceptance remains **200 requirements /111 cases NOT_RUN**. Operating adoption and independent actual-role/device/accessibility/low-bandwidth UAT remain separate gates.
