# Finding-bound corrective plans and exact response review

`LWH-EXT-CORRECTIVE-001` extends the existing institutional finding/response lifecycle. It does not replace the initial application screening sequence, rewrite canonical forms or provide institutional operating approval. Plans use existing protected encrypted journal facts and existing finding projections; no table or migration is added.

The current personally assigned facility respondent proposes an actual action against a real institutional finding ID, with an explicitly supplied future due time, deadline-authority reference, reason and intent. The assigned independent standards reviewer agrees or returns that exact proposal using its immutable plan ID and the finding version. Proposal alone is not agreement. Agreement updates the current due-time projection while the original observed finding, inspector's original deadline, evidence and authorship remain retained. No default deadline, team, officer or authority is created.

The accountable owner is the existing **individual account** assigned through the case's current authority and accepted handover workflow. This is an explicit exception to canonical FRM-010 `owner_team_id`; an account is not silently treated as a team. Actual team governance, canonical tagged capture/missingness and institutional adoption remain open.

New responses require a current independently agreed plan and current scanned evidence for the actual case/criterion. Each response retains the exact plan ID and agreement version. An optional client plan ID, when supplied, must match; old request shapes retain their receipt hash because an omitted/null new field is excluded from canonical request hashing. Historical authorised receipts remain past facts and current authority is checked before replay. A fresh legacy-shaped response is not permitted to bypass the agreed-plan gate.

Response submission does not resolve a finding. The current independent reviewer must review the exact submitted response bound to the current finding version, with actual reason and intent. Resolving rechecks the plan, owner, agreement and current scanned evidence. A returned response permits further actual work; a returned plan requires a fresh proposal/agreement. Revisions retain previous proposals, responses and reviews and require a new response; they never transfer an old resolution to changed work automatically.

The current response and resolved evidence are selected through **protected version-specific submission/resolution facts**, not recording timestamps. This prevents an older response from displacing a newer backdated response or supplying proof for the wrong plan. Unrestricted positive recommendations and decisions still require resolved findings and current evidence. Conditional recognition of unresolved non-MET findings now also requires an actual current agreed plan; it never labels those findings resolved.

Pending respondent/reviewer assignment changes make old plan bindings unusable for new responses/resolution. Actual accepted case handover remains the transfer mechanism; the new owner must propose and agree fresh work. Completed independently verified work retains its original owner and review facts after respondent handover, subject to current evidence and independence checks for a later recommendation. No old authorship is rewritten to the successor. An agreed due time is not an evidence expiry: late actual work can be recorded and independently reviewed without automatically extending the deadline, resolving the finding or making expired evidence current.

Legacy non-MET records with no actual plan remain readable, and compatible authorised response receipts remain replayable, but unplanned legacy resolution cannot grant new positive recognition. While a case is still INSPECTED, the current owner can explicitly propose fresh work, reopening that finding's current projection and retaining old history. Already recommended/decided cases are not silently reopened or backfilled; use the actual reviewed lifecycle/reassessment route. No production conversion fabricates a plan, owner or deadline.

The dossier returns the latest plan independently of history paging and marks whether it still matches the current parties. A scoped, version-paged correction-history endpoint retains proposal, agreement/return, actual response and independent resolution/reason. Ciphertext/storage internals are excluded. The governance UI exposes actual proposals, independent reviews and current-version responses, with context changes clearing prior history.

Files remain excluded without actual scanner/private-storage prerequisites. Metadata-only synthetic CLEAN fixtures qualify no file, malware service, clinical decision or real operating deadline. No notification/backup/clinical-response service is inferred from recording a due time. No Playwright, dependency, extra host, fee or AI approval is introduced.

This advances bounded FRM-010 finding/action/due/response/proof/review semantics in the existing lifecycle. Canonical team ownership, full tagged form capture, safe initial criterion-to-finding linkage, complete notice/appeal/offline semantics and actual-role/device/operating acceptance remain open. Rollback requires a separately qualified schema-9-compatible artifact that preserves newer plans/responses/clinical/finance history and understands these gates; never restore older business data or remove schema markers to reverse code.
