# ADR-0010: Verified recovery, activation packages and bounded cloud operations

Date: 8 November 2026. Status: accepted for the current cloud increment. Implementation contract: `LWH-EXT-CONTROL-001`; this extends the native platform API without changing the archived suite contracts.

The project lead confirmed that offline care is core scope, and that deployments outside the existing Vercel/Neon/Upstash/Resend/OpenRouter stack must be deferred. Offline care is the ability to complete authorised care during WAN loss. Offline installation provisions the local infrastructure required to provide that ability. Deferring installation does not remove offline care from scope or make this WAN-dependent cloud application an offline EMR. No additional host, local database, scanner or browser automation package is installed by this release.

Recovery retains the same account and subject identifiers. Email-token possession needs another proof: the existing authenticator, a one-use recovery code, or two distinct current identity reviewers. Directorate administration alone does not grant identity-review authority. Recovery verifies a replacement authenticator, revokes old sessions and other challenges, and preserves existing grants without renewing expired or revoked professional credentials. Fresh password/TOTP verification protects code generation and staff restriction. Passwords, recovery tokens, pending factors and delivery payloads are never returned by operating worklists or written to audit narratives.

Activation uses an immutable country/operator/custodian package with explicit services, populations/exclusions, processing and storage/backup locations, retention and clinical policy references, coverage, training, restoration, local continuity, support and funding evidence. Distinct current clinical, privacy and technical reviewers must approve; finance review is additionally required when financial policy is included. New/reconfigured activations require a current applicable package. Existing historic activations remain readable and retain their prior authority record. Linked package expiry/withdrawal blocks new writes while preserving record access. Software cannot fabricate the actual source evidence, reviewer appointments or adoption decisions.

Neon is the durable source of job identity, encrypted payloads, leases, attempts and provider outcomes. Workers use PostgreSQL row locking and fencing tokens; unfinished jobs survive process exit. Provider acceptance is recorded only after an actual returned identifier. Resend idempotency is bounded: after the conservative 23-hour window an unresolved job requires operator/provider reconciliation before a new delivery generation. Acknowledging an overdue alert never completes the clinical task. Current source versions and accepted, current coverage are checked again before notification. Changes supersede old alert versions; routing changes retain prior acknowledgement history. Notifications contain neutral sign-in instructions without patient or clinical content.

Vercel runs bounded daily processing and authenticated manual processing. Recovery attempts its exact durable email job after the request transaction commits. A background attempt can be interrupted; the durable job remains available for retry. This is not evidence of continuous clinical escalation or delivered/read email. A future one-shot/continuous worker entrypoint is provided, but no persistent host is provisioned. Malware scanning remains unavailable and unscanned document handling fails closed.

Staff restriction revokes live access immediately and retains historical authorship. A nominated current clinical coordinator offers open clinical work to a qualified successor, who must personally accept the correct subject and current source version. Minimal proposed-handover identity access is separately audited. Other institutional, finance and protected-case responsibilities require review in their own workflows; the response deliberately does not certify universal offboarding completion.

Migration 4 is additive. Deploy the compatible API against schema 3, migrate, then release the frontend. Nine additional immutable history tables receive database protections. Rollback uses the controls feature switch and a compatible API release; retain schema/history and keys. Returning to an older binary does not undo completed credential recovery or staff restriction. Do not drop the schema to roll back.

Full facility-local care still requires the SPEC-017 local API/database/files/identity/policy/jobs/printing/department runtime, bounded offline authority, fenced single-writer epochs, semantic synchronization and tested WAN-loss/reconnect/restore. Its actual deployment remains deferred by the project lead. Full clinical service qualification, scanner hosting, continuous worker hosting, adopted response windows, restoration/key-rotation drills and independent security/accessibility/UAT evidence remain outstanding.

Relevant primary implementation references: [PostgreSQL locking](https://www.postgresql.org/docs/current/explicit-locking.html), [FastAPI background tasks](https://fastapi.tiangolo.com/tutorial/background-tasks/), [Resend idempotency](https://resend.com/docs/dashboard/emails/idempotency-keys).
